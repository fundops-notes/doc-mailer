# 设计稿 v3.1：文档流水线重构（把「附件准备」做成一张可拖动的表）

> 状态：**已实施完毕并验证通过**（用户 Q1–Q5 逐条确认后指示「开始实施」；实现记录见 `docs/HANDOFF_v3.0.md` §14）
> 日期：2026-10-23
> 对外版本号：**3.1.0**
> 前置：`docs/设计稿_v3.0_功能设计.md`（v3.0 总体设计）、`docs/HANDOFF_v3.0.md`（§12 用户反馈轮、§13 概念澄清轮）

## 0. 这一版要解决什么

v3.0 的流水线把「六种步骤 + 输出粒度 + 数据来源」暴露给用户，概念层数太多，实际用起来要理解三套互相缠绕的开关：

- **步骤类型** 6 种（Word模板 / Word→PDF / 加水印 / 加密 / 源PDF / 静态文件）
- **输出粒度** 4 项（每人一份 / 每组合并 / 全员共用 / 按Excel匹配）—— 其中「按Excel匹配」根本不是粒度
- **数据来源** 2 项（从收件人取 / 从外部Excel取）—— 但界面上没有任何地方说明「取的是哪个字段」

用户的真实心智模型（本次反馈的原话）：

> 「文档流水线本身就是个附件准备的过程……我一开始就只有收件人，然后通过文档流水线不断附上附件，通过邮件模板设置模板。然后就生成草稿。」

本稿的目标：**把这个心智模型直接变成界面**，砍掉中间概念层。

---

## 1. 用户主流程（保持不变，只是第 2 步内部大改）

```
事件库 → 新建事件
   │
   ├─ ① 收件人      谁收、多少人、发几封（发送模式）
   ├─ ② 文档流水线   一张表，每行 = 一个要附上的东西
   ├─ ③ 附件        （保留：按全部/指定收件人/按组挂静态文件）
   ├─ ④ 邮件模板     标题 + 正文，{{字段}} 按收件人替换
   └─ ⑤ 预览与生成   预检 → 生成 Outlook 草稿（只建草稿，不发送）
```

第 ①④⑤ 步不动。第 ③ 步（附件）保留但**降级为「不想走流水线时的快捷入口」**，因为流水线里已经有「附加文件」条目了，两者功能重叠。

## 2. 核心模型：流水线从「6 种步骤」改成「2 种条目」

### 2.1 现状的问题

用户反馈原话：**「源 PDF 和静态文件有什么区别？」**

核实结论（v3.0 代码事实）：`pdf_source` 与 `static_file` 在 `execute_step()` 里**是同一个分支**，行为完全一致——把磁盘文件复制进输出目录。真正的区别只在 `word_to_pdf` / `pdf_watermark` / `pdf_encrypt` 这三个「处理型」步骤上，而这三个步骤又恰好是**固定顺序**的（先转 PDF、再加水印、最后加密），拆成三步让用户自己排顺序是没有意义的。

### 2.2 新模型

**流水线上每一行 = 一个「产出条目」，只有两种：**

| 条目类型 | 干什么 | 长什么样 |
|---|---|---|
| **① 生成文档** | 用一个 Word 模板，给每个收件人生成一份内容不同的文档 | 模板路径 + 字段映射表 + 一串处理勾选 |
| **② 附加文件** | 把磁盘上已有的文件放进附件包 | 文件路径（可多条 / 可从 Excel 导入）+ 可选处理 |

**「处理」是条目上的勾选项，不是独立步骤**（对应用户反馈 ③④）：

| 勾选项 | 作用 | 可用范围 |
|---|---|---|
| ☑ 转成 PDF | Word 文档 → PDF（用 Word 导出，格式由 Word 保证） | 仅「生成文档」 |
| ☑ 加水印 | 每人一份的水印文字（默认取该收件人的「水印名称」） | PDF 类 |
| ☑ 加密 | AES-256，打开口令取该收件人的打开口令 | PDF 类 |
| 权限 | 允许打印 / 允许编辑 / 允许复制（详见 §6 待拍板 Q1） | 仅加密时 |

处理顺序固定为 **转 PDF → 加水印 → 加密**，用户不需要理解顺序。

### 2.3 「输出粒度」保留，但含义收窄

粒度仍然需要（它决定产出几份文件），但改名成直白说法，且**挂在条目上**（不再挂在抽象的「步骤」上）：

| 新文案 | 内部键 | 含义 |
|---|---|---|
| 每人一份 | `per_lp` | 每位收件人各得一份，用他自己的字段、水印和口令 |
| 每组合并一份 | `per_group` | 同一合并组共用一份，用组内第一个人的字段 |
| 全员共用一份 | `all` | 所有人共享同一份（口令也共享） |

> 事件级的「发送模式」与条目级的「产出粒度」是两个东西，见 §5 对照表。

## 3. 「数据来源」这个概念整体消解

### 3.1 现状

v3.0 有个步骤级下拉「数据来源：从收件人取 / 从外部 Excel 数据表取」。用户反馈：**「都是『从收件人取』，但其实不知道取哪里」**。

问题在于这个开关粒度太粗：它只说了「大方向」，却没告诉用户**具体哪个字段对应哪个值**，界面里也没有任何地方能预览结果。

### 3.2 新做法：来源下沉到「占位符 → 来源」的映射表里

**删掉步骤级的「数据来源」下拉。** 改成：每个占位符单独选一个**具体来源**。映射表长这样（双击某行改来源）：

| Word 占位符 | 填什么 | 预览（以「甲公司」为例） |
|---|---|---|
| `{{LP_Name}}` | 收件人名称 | 甲公司 |
| `{{Call_Amount}}` | 收件人字段：Call_Amount | 200,000 |
| `{{Fund_Name}}` | 事件常量：Fund_Name | Linear Capital VI L.P. |
| `{{Due_Date}}` | 外部数据表：Due_Date | 2026-11-15 |

来源下拉的候选项：

```
收件人名称 / 水印名称 / 打开口令 / 日期
收件人字段：<收件人表里的自定义列>      ← 来自收件人
事件常量：<事件选项里定义的常量>
外部数据表：<外部表的列>                ← 来自外部 Excel
```

**关键点**：只有当映射表里真的选了「外部数据表：xxx」，才需要配置那张外部表（表路径 + 匹配列 + 下载模板 + 校验）。没选就不显示，界面不会平白多出一堆控件。

> **技术可行性已核实**：`lp_v3.apply_mapping_overrides()` 已经支持 `sheet.XXX` 字段级来源
> （`val = (sheet_row or {}).get(src[6:], "")`），所以这个改造**不需要新写取数逻辑**，
> 只是把「什么时候取 sheet 行」从步骤级改成「映射表里出现 sheet. 来源时才取」。

### 3.3 顺带解决

- 「检测占位符」自动猜来源时，也能猜「外部数据表：xxx」（用外部表的列名匹配），
  猜中就在映射表里预填，**用户不用手工配**。
- 预览值现在直接显示具体值（不只是来源键），用户当场就能看懂。

## 4. 界面改造：步骤链变成一张可拖动的表

### 4.1 布局（替换现在的「步骤卡 + ↑↓ + 参数 + 删除」）

```
┌ 文档流水线 ───────────────────────────────────────────────────────────────┐
│ [＋ 生成文档]  [＋ 附加文件]  [删除选中(2)]  [导入示例链路]   共 3 个条目 │
├───────────────────────────────────────────────────────────────────────────┤
│ # │ 条目名称      │ 类型   │ 来源 / 模板            │ 处理        │ 产出粒度   │ 启用 │
│───┼────────────────┼────────┼───────────────────────┼─────────────┼──────────┤
│ 1 │ 季度对账单    │ 生成   │ 季度对账单模板.docx     │ PDF·水印·加密│ 每人一份   │  ☑   │
│ 2 │ 季度报告      │ 附加   │ 季度报告.pdf (3个)      │ —           │ 全员共用一份│  ☑   │
│ 3 │ 说明函        │ 附加   │ 说明函.docx (1个)       │ —           │ 每人一份   │  ☑   │
└───────────────────────────────────────────────────────────────────────────┘
   ↑ 按住行上下拖动可调整顺序（顺序 = 生成产物的先后，也是附件包内的排列）

┌ 选中条目：季度对账单 ────────────────────────────────────────────────────┐
│ Word 模板：[ C:\docs\季度对账单模板.docx ] [选择…] [检测占位符]          │
│                                                                          │
│ ☑ 转成 PDF   ☑ 加水印   ☑ 加密（AES-256）                              │
│    水印文字：收件人的「水印名称」（留空=收件人名称）                     │
│    权限：[✓允许打印] [☐允许编辑] [☐允许复制]                            │
│                                                                          │
│ 产出粒度：[每人一份 ▾]                                                   │
│                                                                          │
│ 字段映射：                                                                │
│   Word 占位符        填什么                     预览                    │
│   {{LP_Name}}        收件人名称                 甲公司                 │
│   {{Call_Amount}}    收件人字段：Call_Amount     200,000                │
│   [＋ 添加映射行]                                                        │
└───────────────────────────────────────────────────────────────────────────┘
```

### 4.2 交互规则

| 操作 | 做法 |
|---|---|
| 选中 | 单击行 → 下方参数区切换到该条目 |
| 改顺序 | **按住行上下拖动**，拖动时显示插入线；松手即生效 |
| 多选删除 | Ctrl / Shift 多选 → 工具条「删除选中」 |
| 停用 | 「启用」列勾选框，取消勾选 = 这一条不产出（后面的条目照常） |
| 改名 | 双击「条目名称」单元格 |
| 参数 | 直接在下方参数区改，改完即存 |

**删掉**：每行右侧的 `↑` `↓` `参数` `删除` 四个按钮（现在挤在一行里，4 个步骤就 16 个按钮）。

### 4.3 拖动排序的实现

ttk.Treeview 没有内置重排，需要自己实现（约 60 行）：

1. `<ButtonPress-1>` 记下起始行
2. `<B1-Motion>` 算鼠标落在哪一行之间，画一条插入线（`create_line`）
3. `<ButtonRelease-1>` 按插入位置重排 `pipeline` 列表 → 保存 → 刷新表格

多选与拖动冲突时：**按住行拖动 = 改顺序；Ctrl/Shift 点选 = 多选**，用「是否按住 Ctrl/Shift」区分。

## 5. 两个「模式」的对照（这次要在界面上彻底分开）

| | 事件信息 → **发送模式** | 条目参数 → **产出粒度** |
|---|---|---|
| 作用范围 | 整个事件 | 单个条目 |
| 决定什么 | **几封邮件** | **这一个条目产出几份文件** |
| 取值 | 每人一份 / 按组合并 / 全部合并 | 每人一份 / 每组合并一份 / 全员共用一份 |

例：3 位收件人（甲乙同组 G1、丙单独）

| | 每人一份 | 按组合并 | 全部合并 |
|---|---|---|---|
| **发送模式 → 几封草稿** | 3 | 2 | 1 |
| **产出粒度 → 几份文件** | 3 | 2 | 1 |

**界面上的区分措施**：
- 发送模式只在「事件信息」和「收件人」步骤顶部出现，标题写「发送模式（决定几封邮件）」
- 产出粒度只在条目参数区出现，标题写「产出粒度（这一条产出几份文件）」
- 两处各带一句括号说明，鼠标悬停有详细解释

## 6. 数据模型与迁移

### 6.1 新结构

```python
pipeline = [
  {
    "id": "st-xxx",
    "kind": "generate",              # generate | attach
    "name": "季度对账单",             # 条目名（表格显示用）
    "enabled": True,
    "params": {
        "template_path": "C:/docs/季度对账单模板.docx",   # kind=generate
        "files": ["C:/a.pdf", "C:/b.docx"],                # kind=attach
        "to_pdf": True,
        "watermark": True,
        "encrypt": True,
        "permissions": ["print"],     # print | edit | copy
    },
    "granularity": "per_lp",         # per_lp | per_group | all
    "mapping": {"{{LP_Name}}": "name"},   # 占位符 → 来源键
    "sheet": {"path": "", "key_col": "", "match_col": "name"},  # 仅用到 sheet. 来源时才需要
  },
]
```

### 6.2 迁移规则（自动，用户无感）

| v3.0 旧步骤 | → v3.1 新条目 |
|---|---|
| `word_template` | `generate`（`template_path` 搬过去，`mapping.fields` 搬过去） |
| `word_to_pdf` | 并入**上一个** `generate` → `to_pdf = True` |
| `pdf_watermark` | 并入**上一个** `generate` → `watermark = True` |
| `pdf_encrypt` | 并入**上一个** `generate` → `encrypt = True`，`permissions = ["print"]` |
| `pdf_source` | `attach`，`files = [src_path]` |
| `static_file` | `attach`，`files = [src_path]` |

粒度：`mapping.mode` → `granularity`；`mode == "from_sheet"` → `granularity="per_lp"` + 保留 sheet 配置。

迁移在数据层读取时自动完成（`normalize_step` 改成 `normalize_item`），旧文件不需要手工迁移。

## 7. 「附加已有文件」怎么拿到文件路径

按用户反馈⑤（「例如我可以通过 excel 表导入文件路径」），提供三种填法：

| 方式 | 做法 | 适合 |
|---|---|---|
| **手填路径** | 参数区多行文本框，一行一个路径 | 少量文件 |
| **从 Excel 导入** | [从 Excel 导入路径…] → 选表 → 选列 → 全部路径灌进来 | 一批文件路径（如共享盘清单） |
| **从收件人表带出** | 收件人表里的「附件路径」列本来就支持 per-recipient 专属文件，导入收件人时一并带进来 | 每家 LP 一份自己的补充说明 |

> **第三条与流水线条目的区别**（设计稿里要说清）：
> - 收件人表里的「附件路径」= **每人不同的**附件（甲的说明函、乙的说明函…）
> - 流水线的「附加文件」条目 = **一份文件发给多个人**（除非把粒度设成「每人一份」，
>   那样只是文件名里带上收件人名字，内容相同）

## 9. 需要你拍板的 5 个点

| # | 问题 | 我的建议 |
|---|---|---|
| **Q1** | **权限位是否开放成可配置？** v3.0 是硬编码「仅打印」（铁律）。你说的「密码打开后是否可以编辑」需要开放 `PDF_PERM_MODIFY` / `PDF_PERM_COPY`。 | **开放，但默认仍勾「仅打印」**。默认行为不变，用户主动勾才放开。 |
| **Q2** | **「附加文件」条目的粒度要不要给「每人一份」？** 那样内容相同、只是文件名带收件人名字。 | 给（有用：对方能对号入座），但默认选「全员共用一份」。 |
| **Q3** | **收件人表里的「专属附件路径」保留吗？** 它和流水线的「附加文件」功能重叠。 | **保留**（它是 per-recipient 的天然位置），但流水线「附加文件」默认用于统一文件；两者在文档里讲清区别。 |
| **Q4** | **「生成文档」条目可以有几个？** 你的描述像是只有一个（一份模板）。 | **允许多个**（比如对账单用模板A、催缴函用模板B），每个都是独立一行、各自一份产出。 |
| **Q5** | **迁移后旧的 6 种步骤类型在界面上还会出现吗？** | 不出现，全部归并成 2 种条目；迁移自动完成，旧文件打开即新结构。 |
